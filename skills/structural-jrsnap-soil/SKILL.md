# SOIL-JR で SDT を計算し、SDR・SDC を出力する

対象は `SOIL-JR.exe`（開発機の既定のインストール先は `C:\RTRI_Program\JRSNAP(Ver5.3-L01体験版2)`）。ソースは同じインストール先の `SOIL-JR\SOIL-JR.csproj` 以下にある。この版は `.sdt` をコマンドライン引数として受け取らない。`scripts/run-analysis.ps1` が、必要なライセンス引数で起動して画面から読込・計算・連携出力を行う。

## 自動実行

`powershell.exe -STA` を使う。入力と出力は絶対パスに解決され、既存の SOIL-JR プロセスがある場合は別件への干渉を避けるため停止する。インストール先が既定と違うときは `-InstallDir` を渡す。

```powershell
$folder = '<入力 .sdt のあるフォルダーの絶対パス>'
$inputFile = Join-Path $folder '<名前>E.sdt'
$sdrFile = Join-Path $folder '<名前>S.sdr'
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File '<このスキルのフォルダー>\scripts\run-analysis.ps1' `
  -InputPath $inputFile -SdrPath $sdrFile
```

スクリプトは計算完了メッセージと保存ダイアログを処理し、既存 SDR の上書き確認に応答する。実行後、SDR・SDC の更新時刻、サイズ、版情報、入力 SDT と一致するタイトルを確認する。入力 SDT は保存せずに SOIL-JR を閉じる。結果のパスとサイズが出力され、失敗時はエラーになる。

- **画面をキー操作で動かすので、実行中は SOIL-JR とキーボード・マウスに触らない**（利用者にも伝える）。触ると、キーがほかの画面やメニューに届き、意図しない「名前を付けて保存」で入力フォルダーに .sdt が書かれたことがある（2026-10-23）。実行後は入力フォルダーに見覚えのないファイルがないかを確かめる。
- メニューのキー操作は、SOIL-JR が入力待ちになり、メイン画面が最前面になったのを確かめてから送る。開く画面が出なければメニューを閉じて送り直す（3回まで）。確かめずに送っていたときは、1回目にファイルを開く画面が出ずに止まることが3回中3回あった。直したあとは3回とも1回目で通った（2026-10-23）。
- `%TEMP%` の下の深いフォルダー（`AppData\Local\Temp\…\C--…` のような名前を含むもの）に入力を置くと、ウィンドウの表題のパスが途中で切れて「入力 SDT の読込を確認できません」になった。原因は確かめていない。`C:\tmp\…` のような短いパスでは通った（2026-10-23）。
- 同じ .sdt から出し直した .sdr は、置き場所が違ってもバイトまで同じ（3回確認、2026-10-23）。
- 液状化の判定をした .sdt では、`<名前>(液状化時用).sdr`・`.sdcl` も続けて書かれる。スクリプトが確かめるのは通常時の .sdr・.sdc だけ。

## 画面で実行する場合

1. 入力 `.sdt` の絶対パスと、出力の共通ベース名を確定する。既存の `.sdc`・`.sdr` がある場合は、両ファイルの更新時刻とハッシュを控える。SOIL-JR の既存プロセスがあれば、別件の作業中でないか確認してから対象ウィンドウを選ぶ。
2. 起動していなければ、PowerShell から以下のように起動する。作業ディレクトリはインストール先にする。引数の先頭の `LicenseOptNo` と末尾の `Ver.5.3-L00` を省かない。

   ```powershell
   $install = 'C:\RTRI_Program\JRSNAP(Ver5.3-L01体験版2)'
   Start-Process -FilePath (Join-Path $install 'SOIL-JR.exe') `
     -ArgumentList 'LicenseOptNo111111199999999999999Ver.5.3-L00' `
     -WorkingDirectory $install
   ```

3. `地盤反力特性算定プログラム(Ver.5.3-L01体験版2)` の画面で **ファイル → 開く** を選び、入力 `.sdt` を開く。ウィンドウのタイトルに入力パスが表示され、データが読まれたことを確かめる。
4. **計算実行 → 計算実行** を選ぶ。入力エラーや「計算中にエラーが発生しました」が出た場合は止め、表示内容を報告する。入力 `.sdt` を修正して再試行することは別途依頼がある場合だけ行う。
5. **「計算が終了しました。連携ファイルを作成しますか？」** には **はい** を選ぶ。**「基礎照査連携用データの保存」** ダイアログで、希望する出力ベース名に `.sdr` を付けた絶対パスを指定する。既存ファイルへの上書きが依頼されている場合は上書き確認を進める。SOIL-JR は同じベース名の `.sdr` と `.sdc` を続けて書き出す。
6. 両方のファイルが存在し、サイズが正で、今回の実行後に更新されたことを確認する。先頭の `Ver.` と SDR のタイトル、SDC の `【バージョン情報】`・`【杭情報】` を読み、表示された入力のタイトルと一致するか確認する。既存ファイルが残っているだけの場合は成功としない。異常時は元ファイルを保持し、エラーと更新状況を報告する。

## 見本データ

開発機のみ。structural-mcp の repo のルートから `Batch/tests/JRSNAP_Ver5.3-L01体験版2/01_サンプル(V53)：RC橋脚L：PHC/` の `RC橋脚（杭基礎）サンプルデータE.sdt`。保存ダイアログで同じフォルダーの `RC橋脚（杭基礎）サンプルデータS.sdr` の**絶対パス**を指定する。対応する `RC橋脚（杭基礎）サンプルデータS.sdc` も同じフォルダーに生成される。入力の `E` と出力の `S` は異なるため、保存ダイアログの既定名をそのまま使わない。見本は submodule の中のファイルなので、試すときは複製を使う。

Batch の `tests/JRSNAP_Ver5.3-L01体験版2/08_基礎照査連携(V53)/` には、.sdt を書き換えて作った見本（回転杭・中抜きなし）と、SOIL-JR 付属の RC ラーメン（6列×2列）の .sdt・.sdr・.sdc がある（作り方は同じフォルダーの README）。

## 詳しく

- `references/sdr-format.md`：.sdr の段と列、Ver.5.2 と Ver.5.3 の違い、液状化時用、引抜き7列、杭配置情報の有無、方向で値が変わらないこと。
- `references/sdt-format.md`：.sdt の全項目（Ver.5.3。段と欄の意味・単位・コード、入力と画面が求めて保存する値の区別、杭種ごとに使う欄と A・I の式、地盤抵抗係数の既定値、検査、帳票の項目と画面なしで動かせるか、.sdc の構成）と、Ver.5.2 の書式との違い。
- `references/sdt-pile.md`：.sdt の `●杭条件●` の項目（杭種・工法のコード、回転杭の入力欄と A・I の式、杭の配置と中抜き、K_FLG）と、行を書き換えて見本を作る方法。

## 根拠

- `Protect.cs` の `Protection` は `LicenseOptNo` と版番号を確認し、引数なしの直接起動を拒否する。
- `MDIfrmMain.cs` の `FileMenu` は、ファイルを開くときに `Common.DataFileRead`、計算時に `Calc.ResultFile` を呼ぶ。計算成功後の保存ダイアログで出力ベース名を決め、`Output.OutPut_Shousa` と `Output.OutPut_Renkei` を順に呼ぶ。
- `Output.cs` では `OutPut_Shousa` が `.sdr`、`OutPut_Renkei` が `.sdc` を出力ベース名に追加する。液状化の判定をした計算（`J_LiJudgeFlg=1`）では、続けて `OutPut_Shousa_De`・`OutPut_Renkei_De` が `(液状化時用)` を付けた名前で書く。

## 知見を足すとき

SOIL-JR の性質はこのスキル（structural-mcp の `skills/structural-jrsnap-soil/`）を編集し、structural-mcp で commit する。案件の地盤条件や判断はその案件の repo。コードで確かめたこと、実アプリで試したこと、推定を区別し、日付と版を残す。

# JRSNAP の耐震設計総括表（SSheet.exe。Output-JR）

JRSNAP の総括表（M-θ・M-φ 部材の照査をまとめた Excel）を作るのは `SSheet.exe`。解析エンジンや `S_OutputList.exe` ではない。Aggre-SE（Docu-SE）の総括表を JRSNAP と突き合わせるときの基準になる。

## 起動と入出力（コードで確認：5.3-L01体験版2 の `SSheet.exe` と `JRSNAP_Input.exe` の逆コンパイル、2026-10-23）

- JRSNAP_Input の「耐震設計総括表」（メニュー）／「総括表」ボタンが、`SSheet.exe` を引数 `LicenseOptNo…`（`Ver.5.3-L00` など、`run-analysis.ps1` と同じ文字列）で起動する。引数がなければ「直接起動は、できません」で終わる。2桁目の購入フラグが 1 でないと「Output-JRが未購入です」。
- 入力：結果ファイルを2つ選ぶ。ρm=1.2 と ρm=1.0（`.R10`／`.R12`。一括処理用 CSV の列名は「拡張子(R10またはR12)」）。ρm=1.2 と 1.0 の M-θ 要素数が違うとエラー。
- 作成条件：安全性の照査（損傷レベル制限の初期値 3）／復旧性の照査(L2)（2）／使用性の照査(L1)（1）。着目する解析増分ステップ数と、M-θ・M-φ 部材ごとの損傷レベル制限の初期値、総括表タイトル（データタイトル／ファイル名）を画面で決める。
- 出力：結果ファイルと同じ場所に `<名前>_安全性.xlsx`（L2 は `_復旧性L2.xlsx`）。ひな形は `FormSekkei.xlsx`、作業は `WorkOut.xlsx`。出力先に同名があると置換えの確認が出る。
- 一括処理（`cmdIkkatsu`）と、その入力 CSV を作る「一括処理用CSVデータ作成」（`cmdCSV_Make`）がある。
- この画面を自動で操作する道具はまだない（画面で出す）。MCP のツールもない。

## 見本（実ファイルで確認、2026-10-23）

structural-mcp の repo のルートから `Batch/tests/JRSNAP_Ver5.3-L01体験版2/01_サンプル(V53)：RC橋脚L：PHC/` の `…(Case2_ρm12_αf1_正向)_安全性.xlsx`（5.3、2026-10-12 に出力）と、`Batch/tests/JRSNAP_Ver5.2-L03/…PHC/` の `…_復旧性L2.xlsx`（5.2、L2）。

- シートは「重要な解析条件と解析結果(ρm=1.2)」「(ρm=1.0)」「M-θ」「M-φ」。M-φ は10要素ずつ6ブロックが縦に並ぶ（`xls` より行が数行ずれる。行は左の見出し「応答部材曲率：φd(1/m)」などで探す）。
- **損傷レベルの θd・φd と制限値 θ1〜3・φ1〜3 は小数点以下7桁**（例 θd 0.0607667、φ1 0.0041332）。比（γi･φd/φ1 など）と軸力は従来の桁。
- 同じ場所の `…(Case…).xls`（2026-09-23 付、6桁）は古い版の出力で、値も違う（φ1 が 0.004134）。**比較の基準にしない。** どのプログラムが書いたかは調べていない。
- Excel の値は openpyxl（`data_only=True`）で読める（`.xls` は xlrd）。

## Docu-SE との突き合わせ（2026-10-23、Batch の runner に7桁の書式を入れたもの）

`ExcelReport.vb` の損傷レベル3か所（M-θ／M-φ の φr・φi）を `"0.0000000"` にして `summary.xlsx` を作り、上の5.3 の `_安全性.xlsx` と比べた。V53 の PHC で、M-θ（く体）と M-φ（杭の10要素）の φd/θd・N・制限値1〜3・比・損傷レベルが7桁まで全部一致した（軸力の差0）。この比較は、要素を φd の一致で対応づけて行う（Docu-SE の総括表は区間ごとの決定ケースで、JRSNAP の要素の列と並びが違う）。同じ φd の要素が複数あるときは軸力と制限値で選ぶ。「損傷レベルの制限」の欄は、JRSNAP が出力時の作成条件（3）、Docu-SE がプロジェクトの設定なので、条件を揃えないと違って見える。

# 照査の中身と結果の読み方

WebPier の README・CONTEXT.md と WebPier の開発用スキル（webpier-foundation・webpier-capacita・webpier-aggrese・webpier-footing・webpier-cantilever。2026-10-19 に foundation-check・footing-check・cantilever-check から改名）のうち、計算書を使う人に要る部分。確かめた版：WebPier `b6c349c`（2026-10-19）。式や定数を変えるのは WebPier の開発の作業（WebPier の repo）。

## 共通の考え方

- **印字桁で計算する**：計算書に印刷する値は内部でも印字桁に丸め、後続の計算はその値を使う。印刷物の数値だけで検算できる。見本（Excel の計算書）と末位が 0.01 程度違うのは、見本が丸めない中間値で計算しているため。
- **元 Excel の誤りは再現しない**。見本との差のうち設計上残しているものは WebPier の README の「Example2 との既知の差」。
- **実行の成否と判定は別**：`ok: true` で `engineeringStatus: not_ok` は普通にある。NG でも生成は止まらない。
- **判定を返すのは 0612・0622 だけ**。Capacita（0611・0621・0810・0820・0910）と Aggre-SE（0711・0721）は判定を返さないので `not_evaluated`。OK/NG は差し込まれたページで読む。照査を実行したことを合格とみなさない。

## 0500 直接基礎・0600 上部工反力・0610/0620 荷重

- 0500：地盤ばね（kv・Kv・ks・Ks・Kr、長期・短期、2方向）と支持力係数（表の中間は線形補間）。平坦な一層の土被りなら、JRSNAP に渡す有効根入れ深さ Df と平均有効単位重量 γ2 も印刷する（Df は形状と表層厚から。地盤調査の層厚から別に取らない）。
- 0600：死荷重・雪荷重（2・10・30年確率）、橋脚自重・上載土・浮力、移動荷重の反力、方向別の荷重。空き支承枠は除き、支承は入力の枠の番号（G1〜G10）で示す。
- 0610：20基本ケース・16組合せ・8抽出。0620：17基本ケース・15 Define・16組合せ・8抽出。荷重図は FEMPython が FrameWeb 入力から描いたページ（1ページ2ケース）。
- FrameWeb 入力（`post/線路方向.json`）は FrameWebforJS/CS の保存形式。座標は現行形式（y 下向き）で、ブラウザ版の FrameWebforJS で開くと上下逆になる。FrameWebforCS の画面で保存し直すと数値の精度が変わるので、別名で保存する。

## 0611・0621 柱の断面照査（Capacita）

- 骨組解析（FEMPython）のピックアップ（`*.pik`）を設計応答値として、柱下端の1断面を Capacita が照査する。WebPier は見出しと解説だけを描き、各節の後に Capacita の計算書のページを差し込む：8.5 断面力の総括、8.6 安全性（破壊）の曲げ・せん断、8.7 耐久性の曲げひび割れ・せん断ひび割れ、8.8 使用性（外観。外観の照査を「行わない」なら置かない）、8.9 復旧性の曲げ・せん断（0621 は 9.5〜9.9）。
- 断面力が0で Capacita が照査を飛ばした節（RC標準の省略の規則）は、ページを差し込まずに省略の理由の1文を印刷する。直角方向は永久作用が左右対称なので、せん断ひび割れと使用性が省略されることが多い。
- 公開する `post/線路方向.wdj` は Capacita が取り込んだ完成の WDJ で、Capacita の画面で開ける。
- 安全係数・fsu・kr・k4 は WebPier の定数（復旧性（地震時以外）の γi は運輸機構・JR各社 1.2、JR東日本 1.0）。入力は `柱の断面照査` の環境条件・外観・ε'csd・機関・JR-001/004。
- 差し込む Capacita のページは、本文が同じでも書体のサブセット名が毎回変わるのでバイトが変わる（実アプリで確認、2026-10-19）。

## 0612・0622 基礎の照査（WebPier が判定する）

- 設計応答値は骨組解析の `*_ピックアップ反力.csv` のうち、フーチング底面の中心のばね支点の反力（Vd＝−fy、Hd＝|fx|、Md＝|mz|。2桁に丸める）。荷重から組み立て直さない。
- 4列：長期支持（抽出ケース7、鉛直反力が最大）、短期支持（8、同）、安全性の鉛直力最大（6 の鉛直反力が最大）、安全性の曲げ最大（6 の |mz| 最大）。
- 鉛直支持：γi・γa・pd1／qd（長期・短期）、γi・γa・Vd／Rvd（安全性）。qd は「砂質土の場合」の式 qvd＝frγ・Iγ・βb・Be・γe1・Nγ＋frq・Iq・γe2・Df・(Nq−1)、qd＝qvd＋γe2・Df。支持層は砂質土・砂礫だけ（粘性土・互層は入力エラー）。
- 長期の qd の上限：砂質土 300＋γe2・Df、砂礫 500＋γe2・Df。Df は 0500 の表層厚。γe2 は長期が平水位、短期・安全性が高水位（水位は基礎下面から）。
- 回転：γi・γa・ex／制限値（長期 B/6、短期 B/4）、安全性は γi・γa・Md／Mmd（Mmd＝Vd・B/2・(1 − Vd／(qd・B・L))）。
- 水平支持：γi・Hd／Rhd（Rhd＝frs・Vd・tanφ、frs＝0.33、全列 γi＝1.0）。
- 地盤抵抗係数・γi・γa・回転の制限値は WebPier の定数。照査値と ＯＫ／ＮＧ を表に印刷し、結果 JSON の `result.engineering_status` が `ok`（すべて満足）か `not_ok`（1つでも NG）。
- 合力の作用位置がフーチングの外、鉛直力が上向き、反力が読めないときは生成が止まる。
- 見本（Example橋脚2）の Df 3.78 は地盤調査の表層厚で、WebPier は形状からの表層厚（4.70）を使う。見本と値が違うのはこのため。

## 0710・0720 地震時荷重・0711・0721 静的非線形解析と耐震性能照査

- 0710：8基本ケース・1組合せ（地震は起点側 ← の片方向）。0720：9基本ケース・上り線・下り線の2組合せ（地震は → の片方向）。柱下端に 0.010 m の微小部材を置く（JRSNAP の M-θ 部材）。計算書に JRSNAP のデータ確認図（非線形番号図・断面番号図・要素関連データ一覧表・断面詳細図・節点ばね分布図）と荷重図を差し込む。JRSNAP のページはヘッダーに印刷日が入るので日ごとにバイトが変わる。
- 0711・0721：NDU を JRSNAP で静的非線形解析し（確認には「耐力と変形性能の自動算定」は初期のまま実行、「基礎照査機能」は「いいえ」と答える）、その結果を Aggre-SE で耐震性能照査する。**計算書は Aggre-SE の帳票そのもの**（見出しも節の番号も足さない）。判定（損傷レベル、基礎の安定）は帳票で読む。
- 耐震照査の条件は `耐震設計条件`（地域別・地盤区分）だけが入力で、ほか（スペクトルⅠ,Ⅱ両方、照査項目 ④ 以外、損傷レベルの制限値など）は WebPier の定め。
- 既知の差：WebPier の NDU は JRSNAP の基礎照査のデータを持たないので、Aggre-SE は直接基礎の照査値を DB1 から求める。作用は見本と一致し、抵抗側（Rvd など）は違う。

## 0800〜0820 フーチング

- 0800：方向ごとに基礎底面の中心の設計応答値5列（安全性 Md最大・Vd最大、使用性 短期・長期は骨組解析の反力の断面照査用ピックアップ、地震時は 0711・0721 の直接基礎のステップ表で Vd が Rvd に初めて達したステップ）から、地盤反力の分布（Case 1〜4）、張出し（起点側・終点側のうち Md の大きい側）の断面力、有効幅、せん断スパン La を求める。判定はない。
- 0810・0820：その応答値を書いた WDJ を Capacita が照査（安全性の曲げ・せん断、耐久性の曲げひび割れ、復旧性（地震時）の曲げ・せん断）。判定は差し込んだページで読む。
- 既知の差：張出しの柱前面の地盤反力度 q2 は原資料の式を直している（安全性・使用性の Md・Vd が見本より大きい）。

## 0900・0910 片持ち梁

- 0900：はりの左右の張出し（|支承位置| > W6/2 の支承が載る側）について、死荷重、3つの列車荷重（B支点最大・C支点最大・B+C支点最大）と衝撃、車両横荷重・風・地震時のトルクによる鉛直反力、ゴム支承とストッパーの水平荷重、自重から柱前面の Md・Vd・Mt を求め、31ケースの組合せから照査ごとに最大を採る。地震時の震度は 0711・0721 の総括表の最大応答震度（全 Case・復旧性/安全性の最大）。
- 0910：その採用値を Capacita が照査（安全性（破壊）、安全性（疲労破壊）、耐久性、使用性（外観の照査を行うとき）、復旧性）。判定は差し込んだページで読む。
- 支承の水平荷重は 0600 とは別のモデル（可動はゴム支承 μ·Rm、固定はストッパー）。

## 判定を読むとき

- 0612・0622：結果 JSON の `result.engineering_status` と、計算書の表の ＯＫ／ＮＧ。
- それ以外：計算書の該当ページ（Capacita・Aggre-SE の照査値と制限値）。PDF のページを画像にして読むと確実（Capacita・Aggre-SE のページは文字の取り出しが崩れることがある）。
- NG のとき：WebPier は寸法・配筋を変えない。どの照査がどれだけ超えたかを利用者に報告し、寸法・配筋の決め直しは利用者が判断する。

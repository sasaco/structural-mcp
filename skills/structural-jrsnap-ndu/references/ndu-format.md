# 直接基礎・支点・全体の設定と、読込・保存の性質

## 直接基礎の支点と別枠の照査データ（2026-10-17、旧版 5.1 の橋脚の NDU を見本 PDF と NDT で照合して観測）

- 座標：NDU の座標原点は任意の節点（観測したモデルでは節点5）、y は下向きだった。原点や符号の違いを形状不一致とみなさない。`-2.980232E-07` のような値は NDT の表示精度では 0.000 で、ゼロへ修正しない。
- 長さ 0.010 m の非線形要素（他は剛域）があっても、全長に 0.010 m を足さない。
- 直接基礎のモデルは `SuppotNum=3`、`SuppotRow=2`、`FootRow=1` だった。並進ばね2行と直接基礎回転ばね1行を合わせた3支点データで、NDT にも3行がある。杭周面支持専用の `SuppotNum=SuppotRow` という部分仕様を直接基礎へ流用しない。
- 解析用の `FootInfo<n>` は節点、B、L、kv（kN/m³）、Df（m）、φ（度）、KR2 などを持ち、第10フィールドが平均有効単位重量 γ2（kN/m³）。見本の表示値（例：Df=3.8）は丸めで、入力（3.78）を丸めた表示値へ変更しない。
- `CHOKU_KISO<n>` は別枠の照査用データ（継続行がある）。解析用 `FootInfo` と同一の入力だと決めつけない。見本に入力表がなく、意味・同値性の全確認はできていない。解析入力が一致しても基礎照査設定全体の再現を保証しない。
- `ChokuKisoNum`・`CHOKU_KISO<n>`・`CHOKU_KISO_Link<n>=1,<節点>`（照査位置）があると、解析後に JRSNAP の基礎照査機能（`S_SubstCheck.exe`）が `<DB1名>_Output_Chokukiso.csv` などを書け、Aggre-SE の直接基礎の照査はその値を使う。`ChokuKisoNum=0` だと Aggre-SE は DB1 から求める（スキル `structural-jrsnap-input` の engine.md、スキル `structural-aggrese`）。
- `SoilRenkeiFile<n>`（SOIL-JR 連携の旧絶対パス）、`NDTPath`（旧出力先）、`Tisou`（地層）に古いデータが残っていることがある。根拠がなければ保持し、再連携・再出力を行わず未確認として報告する。

## 旧版のファイルを 5.2・5.3 で保存したときに足される項目（2026-10-17、`Virsion=5.1.10.S.4` の1件で実測）

スキル `structural-jrsnap-input` の save-ndu.ps1 の検査モードで、インストール済み V52/V53 の読込・保存処理を一時コピーに実行した。両版とも再保存がバイト一致し、保存された本文は同一で、ヘッダーはそれぞれ `5.2.3.S.4` / `5.3.1.S.6`。原本との差は、ヘッダー以外では次の7項目だった。

1. `DataInfo` 末尾に `,0,0,0`。
2. `SectInfo<n>` 末尾に `,0,0`。
3. `TanbuShiji<n>=0,0` 行追加。
4. `SectSafe<n>` 末尾に `,1.3`。
5. `FootInfo<n>` 末尾に `,20,-3.402823E+38`。
6. `CHOKU_KISO<n>` の先頭行末尾に `,20`。
7. `NDTPath` 行削除。

これは1つのモデルに対する保存処理の実測で、マニュアルの新版既定値を旧モデルに一律適用しない。行追加による位置ずれを含む `BodyChangedLines=137` は、137個の入力値が変わったという意味ではない。原本へ新版保存を反映する場合は実際のキー単位の差分を確認する。

## 5.2-L03 の読込の制約（2026-10-17、インストール済み 5.2-L03 の読込・保存処理で一時モデルを確認）

- reader は行の位置と順番に依存する。キーが同じでも `Member_BunpuBane` や `ShabuzaiMeInfo` を別ブロックへ移すと読込に失敗する。名前を辞書へ読み込めただけでは実アプリ互換を保証できない。
- `TishouNum=0` にしても `Tisou=` の空行は必要だった。行ごと削除すると後続読込で空文字から Byte への変換に失敗した。不要な旧地層の値を除くことと、構文上必要な空レコードを除くことを区別する。
- 1要素1部材の構成、`ChokuKisoNum=0`、照査リンク無効、`SRenkeiNum=0`、`TishouNum=0` のモデルでも、解析用 `FootInfo` を保持して読込・保存できた。旧照査・連携データを新規のモデルへ自動コピーする必要はない。
- `DataInfo` 第20フィールドの 0.001 は収束判定値 FTM で、変位増分そのものではない。変位目標値と増分数は別項目。
- `TanbuShiji=0,0` は断面照査側の部材端条件で、骨組の基礎支点条件ではない。
- `SectJikuNum` の上下面引張主筋段数は、上面距離順の全配筋から先頭／末尾 N 段を選ぶ。選択方向の入力行数だけを数えると、側面筋が外側や段間に入る配置で異なる鉄筋を選ぶ（操作説明書 90・530頁、内部の DRTU/DRTL/DRTUV/DRTLV）。
- 実アプリの保存で数値の字面が正規化されるため、バイト差分に加えて意味と参照の照合が要る。
- NDU の読込・再保存は、画面の確認、NDT 出力、解析実行、耐震安全性の確認を意味しない。
